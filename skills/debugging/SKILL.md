# 系统化调试指南

## 适用场景

测试失败、行为异常、间歇性缺陷。核心原则：**先理解，再修复**——禁止"试一下改改看"。

## 四阶段流程

### Phase 1: 重现（Reproduce）

- 建立最小可重现案例（剥离无关依赖）
- 确认重现率：100%？偶发？与环境相关？
- **证据**：保存失败测试的完整输出

### Phase 2: 定位（Isolate）

二分法缩小范围：

```bash
# 二分提交历史
git bisect start && git bisect bad && git bisect good <已知好提交>

# 二分输入数据（最小化触发输入）
```

- 加临时日志/断点，观察**真实状态**而非推测状态
- **证据**：指出确切的文件与行号

### Phase 3: 根因（Root Cause）

区分三类原因：

| 类型 | 特征 | 修复策略 |
|------|------|---------|
| 实现错误 | 逻辑与意图不符 | 修正实现 |
| 规格缺失 | 意图本身不明 | 先补测试定义预期行为 |
| 环境问题 | 本地过/CI 挂 | 对齐环境，勿改产品代码迁就 |

问三次"为什么"：直接原因 → 促成条件 → 系统性缺口。

### Phase 4: 修复与验证（Fix & Verify）

1. **先写一个会失败的测试**复现该缺陷（回归测试）
2. 确认测试失败（RED）
3. 修复（最小改动）
4. 确认新测试通过 + **全量测试通过**（GREEN）
5. 删除临时日志

## 防御加固（Defense in Depth）

修复后检查同类风险：

- 相同模式还存在于哪些调用点？
- 是否应该加一个校验/断言防止复发？
- 是否值得在 AGENTS.md 或技能文档记录此坑？

## 反模式（禁止）

- ❌ 不重现就改代码
- ❌ 用 try/catch 吞掉异常让测试"变绿"
- ❌ 放宽断言迁就错误行为
- ❌ 修复后只跑单个测试不跑全量
